## 📘 Contibuições

O **SAGE Education** é um projeto ***livre e gratuito*** para ***educadores, instituições de ensino e governos***. Toda contribuição é bem-vinda, e há várias formas de participar, muitas delas não exigem conhecimentos técnicos de programação.

Antes de contribuir, por favor leia o nosso [Código de Conduta](https://github.com/comunidade-do-saber/sage-edu/blob/main/CODE_OF_CONDUCT.md).

---

### 🌍 Tradução do Software

A atualmente o **SAGE Education** está disponível apenas em **português** e **inglês**. A expansão para novos idiomas é essencial para ampliar o impacto do projeto e garantir que possa ser utilizado na língua nativa de cada utilizador.

Você pode contribuir de duas formas:

* **Melhorando as traduções existentes**
* **Criando uma nova tradução** para o seu idioma

Traduzir o **SAGE Edu** é simples e não requer conhecimentos avançados. Basta copiar um arquivo `.po` e ajustar o seu conteúdo conforme o idioma desejado, para o caso de novas traduções.

#### 🤖 Filosofia de Engenharia: Compreensão sobre Automação

O nosso objetivo principal é construir uma base de código robusta e mantível, garantindo que cada programador compreende profundamente o software que está a construir. Priorizamos a compreensão humana, a prática deliberada e a verdadeira propriedade do código em detrimento da velocidade de geração automatizada. **Escrevemos código para o entender, não apenas para o entregar.**

**A Regra "Sem Agentes Autónomos"**
- **Proibida a geração de código por IA:** o uso de agentes de codificação autónomos (ex: Cursor, GitHub Copilot, Devin) para escrever, autocompletar ou injetar diretamente código na base é estritamente proibido.
- **Proibido copiar e colar cegamente:** os programadores não podem copiar código de uma saída de IA e colá-lo diretamente no seu IDE.

**Uso Aceitável de IA (como tutor, não como digitador)**
- **Compreensão conceptual:** os programadores podem usar IA para explicar conceitos complexos, depurar erros lógicos ou sugerir padrões arquiteturais.
- **A obrigação de reescrever:** se um programador usar IA para entender uma solução, deve fechar o chat, internalizar a lógica e **digitar/reescrever o código manualmente a partir da sua própria compreensão**.
- **Verificação:** se um programador não conseguir explicar *porque* uma peça de código funciona, linha por linha, não a compreende o suficiente para a comprometer.

**Propriedade e Responsabilidade do Código**
- **Propriedade total:** o programador que compromete o código é 100% responsável por ele. "A IA escreveu" ou "Encontrei na internet" nunca é uma justificação aceitável para um bug ou má arquitetura.
- **Explicabilidade:** todos os programadores devem ser capazes de justificar as suas escolhas arquiteturais, nomes de variáveis e fluxos lógicos.

**Padrões de Revisão de Código**
- **O teste "explica isto":** durante uma revisão de pull request, os revisores podem pedir ao autor que explique blocos específicos de código. Se o autor não conseguir explicar claramente a lógica, o PR será rejeitado, independentemente de o código funcionar tecnicamente.
- **Foco na intenção:** os revisores devem focar-se em se o código está alinhado com o modelo mental da equipa e com a arquitetura do projeto, em vez de apenas na sintaxe.

**Aprendizagem Contínua e Maestria**
- **Abrace a dificuldade:** depurar e descobrir lógica complexa manualmente é uma funcionalidade, não um bug. É assim que os programadores dominam a base de código.
- **Partilha de conhecimento:** quando um programador resolve um problema difícil (com ou sem assistência de IA), deve documentar o *conceito* e partilhar a *compreensão* com a equipa, garantindo que toda a equipa evolui.

Seja consciente e respeitoso com os outros. Leia mais sobre a nossa filosofia em [dontpastetheai.com](https://dontpastetheai.com) (em inglês).

### 🐞 Reportar Bugs

Como em qualquer software, erros podem ocorrer. Estamos sempre a trabalhar para os identificar e corrigir, mas a comunidade desempenha um papel fundamental neste processo.

Se encontrar algum bug, comportamento inesperado ou falha, pedimos que comunique através dos canais oficiais do projeto. A sua ajuda contribui diretamente a melhorar a qualidade e estabilidade do sistema.

---

### 🔒 Reportar uma Vulnerabilidade de Segurança

Vulnerabilidades de segurança são tratadas separadamente de relatórios de bugs regulares — **não** abra um issue público. Consulte [SECURITY.md](https://github.com/comunidade-do-saber/sage-edu/blob/main/SECURITY.md) para instruções sobre como reportar uma vulnerabilidade em privado.
